# Database Migrations

HexBuffer Framework generates raw SQL migration files and integrates with `sqlx-cli` to manage schema evolution.

---

## Migration Files Location

All migrations live in the `migrations/` directory in your project root:

```text
migrations/
├── 0001_init_schema.sql          # Auto-generated by hb-cli new
├── 1753710000_create_orders.sql  # Generated by hb-cli migrate create
└── 1753720000_add_user_roles.sql
```

---

## Managing Migrations with `hb-cli`

### Create a New Migration

```bash
hb-cli migrate create
```

Interactive prompt asks for migration name (e.g. `create_orders_table`).

Generated file: `migrations/<unix_timestamp>_<name>.sql`

```sql
-- Migration: create_orders_table
-- Created at: 1753710000

CREATE TABLE IF NOT EXISTS create_orders_tables (
    id VARCHAR(255) PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Run Pending Migrations

```bash
hb-cli migrate run
```

Requires `DATABASE_URL` to be set. Internally delegates to:

```bash
cargo sqlx migrate run
```

> **Note:** Install `sqlx-cli` first: `cargo install sqlx-cli --no-default-features --features native-tls,postgres`

### Check Migration Status

```bash
hb-cli migrate status
```

Lists all `.sql` files in `migrations/` directory.

---

## Initial Migration

`hb-cli new` automatically generates an initial migration at:

```
migrations/0001_init_schema.sql
```

```sql
-- Migration: init_schema
-- Created at: 0001

CREATE TABLE IF NOT EXISTS users (
    id VARCHAR(255) PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

---

## Direct `sqlx-cli` Usage

You can also use `sqlx-cli` directly for more control:

```bash
# Install sqlx-cli
cargo install sqlx-cli --no-default-features --features native-tls,postgres

# Set database URL
export DATABASE_URL=postgres://postgres:postgres@localhost:5432/myapp

# Create migration
sqlx migrate add create_users_table

# Run all pending migrations
sqlx migrate run

# Revert the last migration
sqlx migrate revert

# Check status
sqlx migrate info
```

## Schema Conventions

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `VARCHAR(255)` | Application-generated string ID (e.g. `usr_<timestamp>`) |
| `name` | `VARCHAR(255)` | Display name |
| `created_at` | `TIMESTAMPTZ` | Auto-set to current time |

Modify generated SQL files freely to match your actual schema requirements before running.
